The line Cookie exists: false is the smoking gun here.

This tells us that when your frontend JavaScript makes the POST request to /api/listings/80/contact, it's not sending the authentication cookie.

If the backend route /api/listings/:id/contact requires user authentication (which it almost certainly does, to know who is sending the message and to prevent abuse), and it doesn't receive the auth cookie, it will either:

Immediately reject the request (which might result in a 401 or 403, though a misconfigured error handler could turn it into a 500).
Attempt to proceed without a req.user object (or similar), and then crash when it tries to access a property of this undefined user (e.g., req.user.email), leading to a 500 error.
This means that even if the OAuth2 credentials for sending email are perfect, and even if the email service itself is perfect, the request is failing before it even gets to the point of properly trying to send an email because the user making the request isn't properly authenticated from the server's perspective for that specific API call.

Why this might be happening in production:

Cookie Configuration on Login: The primary suspect is how the authentication cookie is set when the user logs in. For production HTTPS sites, the cookie must be set with the Secure: true flag. It also needs appropriate SameSite, Path, and possibly Domain attributes.
Secure: true: Ensures the cookie is only sent over HTTPS.
Path: '/': Ensures the cookie is sent for all paths on your domain.
SameSite: 'Lax' is common. If it were 'Strict', it might cause issues with certain navigations. If it's 'None', Secure: true is mandatory. Given your request origin and URL are the same, 'Lax' should be fine.
Mismatched Domains/Subdomains in Cookie Settings: If the cookie was set for www.barefootbay.com but the API request goes to barefootbay.com (or vice-versa) and the Domain attribute isn't set correctly to cover both.
Frontend State vs. Actual Cookie: The frontend might think the user is logged in, but the browser might have discarded the cookie or isn't sending it for the reasons above.
