
Goal
Add per-user read / unread tracking for forum threads and forum categories, plus a “Mark All Read” control, so each signed-in user sees:

Thread-level badge on /forum/<category>/ whenever a thread contains a new comment the user hasn’t viewed.

Category-level badge on /forum/ if any thread inside that category is still unread for that user.

State flips to “read” immediately after the user loads the thread (or when they click Mark All Read).

Implementation Guide (no code)
Persistent read-state

Introduce a new persistence layer entity that associates a user with a thread and stores:
last_read_post_id and last_read_at.

Make sure it’s indexed for user × thread look-ups and bulk updates.

Updating the state

When a user successfully renders a thread page, upsert their row in the read-state store to the thread’s current last_post_id and NOW.

Place this after authentication/authorization but before returning the HTTP response so failed loads don’t mark as read.

Computing unread flags

Thread list: compare the thread’s last_post_id (or updated_at) to the user’s stored last_read_post_id.

Forum category list: flag the category as unread if any thread inside it is unread. Choose the most efficient approach for the existing ORM (subquery, eager-loaded boolean, or cached column).

UI / UX cues

Add a visual change (e.g., bold title, colored dot, or badge count) for unread items.

Ensure the cue appears both at thread level and rolls up to category level.

Provide a Mark All Read button at category and/or global level that bulk-updates (or inserts) the user’s read-state rows.

Routes / controllers

Expose an endpoint to handle Mark All Read. It should be CSRF-protected, accept the scope (category vs. global), and redirect back.

Reuse existing auth middleware so the operation applies only to the current user.

Tests

Unit-test: read-state upsert logic and unread calculations.

Integration-test: full flow—new comment → unread badge appears → visiting thread clears badge.

Performance / edge cases

Add proper DB/collection indexes for write and read paths.

Handle first-time visitors (no read rows) gracefully.

Decide whether to prune or archive old read-state records if the community grows significantly.

Migrations & deployment

Generate a migration for the new table/collection and apply it in staging before production deploy.

Verify backward compatibility; existing users should see everything as read until they revisit.

Deliverable
Fully integrated feature respecting the existing codebase conventions, with automated tests passing and UI consistent across desktop and mobile breakpoints.
